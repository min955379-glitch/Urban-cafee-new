## 4. Design Research (do this before coding)

Research how professional cafe and restaurant websites are designed, then record what you found and your decisions in DESIGN.md.

### 4.1 Fonts
- Look at well-made websites for premium cafes, coffee roasters, steakhouses and modern restaurants. Note which typefaces they use for headings and for body text.
- Choose **one heading font and one body font** from Google Fonts that fit this kind of business: elegant or characterful headings, highly readable body text, and good rendering on cheap Android phones.
- Explain in DESIGN.md why each font was chosen and what alternatives you rejected.
- Do not use default or overused choices just because they are common (for example, a plain system font stack or a generic template pairing).
- Load fonts efficiently (preconnect, only the weights used, font-display: swap).

### 4.2 Colors
- The look must not resemble typical AI-generated palettes (no generic dark gray plus orange, no default purple or blue gradients, no neon, no flat template colors).
- Use **premium, food-inspired colors drawn from ingredients**, for example the tones of roasted coffee, cocoa, saffron, paprika, chili, basil, olive, tomato, cream, butter, caramel, wine, and charred wood. Choose a refined subset of these, not all of them.
- **Headings and section titles** should use these ingredient-inspired colors (for example a deep espresso, paprika, or olive tone) so the typography carries the brand. The main hero heading and the section headings may each use a different ingredient color from the palette, as long as the result stays consistent and readable.
- **Check the brand first.** Look at the cafe's logo and its Facebook page (profile picture, cover photo, buttons and imagery) and any public photos of the venue. If the logo colors can be identified, build the palette around them. If they cannot be confirmed, say so in DESIGN.md and use your researched palette as a clearly labeled placeholder that is easy to swap.
- Define the final palette as CSS variables: background, surface, primary text, heading colors, primary accent, secondary accent, button colors, border, and state colors. Keep it to roughly 5 to 7 core colors.
- Make sure every text and button color combination meets WCAG AA contrast.
- Record each color's hex code and the ingredient or brand source it comes from.

### 4.3 Layout and style
- Study how premium cafe sites handle the hero, menu layout, gallery, and booking sections. Aim for generous spacing, a clear visual hierarchy, and subtle details (soft shadows, fine dividers, tasteful hover states) that make it feel hand-designed.
- Avoid the look of a template: no repeated identical card grids everywhere, no stock gradient blobs, no oversized rounded buttons on everything.

## 5. Icons and No-Emoji Rule

- **Do not use emojis anywhere**: not in the interface, buttons, headings, code comments, content, documentation files, commit messages, or placeholders.
- Use **icons everywhere** an icon is helpful. Use one consistent inline SVG icon set (for example Lucide, Phosphor or Tabler, copied as inline SVG so no heavy library loads). All icons must share the same stroke width and size scale.
- Icons are needed for at least: phone, WhatsApp, location pin, clock, search, cart, plus and minus, close, menu (hamburger), star, calendar, users (guests), directions, email, Facebook, TikTok, Instagram, and food category icons where useful.
- Decorative icons get aria-hidden="true". Icons that act as buttons get an accessible label.

## 6. Stack

- Plain HTML, CSS and vanilla JavaScript: index.html, styles.css, script.js, menu.json, /images. No frameworks, so it deploys free on Netlify or Vercel.
- Mobile-first. Fast: lazy-loaded images, no heavy libraries.
- Accessible: semantic HTML, alt text, visible focus states, keyboard navigation.
- A config block at the top of script.js (WHATSAPP_NUMBER, PHONE_1, PHONE_2, EMAIL, FACEBOOK_URL, TIKTOK_URL, INSTAGRAM_URL, HOURS) so everything can be changed in one place.

## 10. Layout and Button Placement Rules

Everything must be fully visible and correctly placed. Nothing may be hidden, cut off, overlapping, or misaligned.

- Every button sits in its logical place: primary action buttons in the hero and header, "Add" buttons aligned consistently inside each menu item, the cart button in a fixed, reachable position, form submit buttons directly below the last field.
- All buttons have the same height, padding, radius and typography within their type (primary, secondary, icon). Labels never wrap awkwardly or overflow.
- Touch targets are at least 44 by 44 px on mobile.
- No horizontal scrolling at any width. No text clipped by containers. No elements covered by the sticky header or sticky bottom bar.
- Consistent alignment: all section content shares the same container width and left edge, icons align vertically with their text, prices align in a column.
- Every interactive element has a visible hover, focus and active state.
- All text is readable against its background at every size.
- Check the cart drawer, mobile menu, lightbox and forms: each must open, close and scroll correctly, and every close button must be visible.
